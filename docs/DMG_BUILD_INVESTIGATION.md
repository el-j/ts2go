# DMG Build Investigation & Comprehensive Fix Plan

## Problem Summary

**Local Build Issues:**
- Local `make build-desktop` fails with: `failed to bundle project error running bundle_dmg.sh`
- The .app bundle is successfully created at 228MB
- bundle_dmg.sh exists and is executable but fails with "Not enough arguments"
- Build terminates with `make: *** [build-desktop] Error 1`

**CI Build Issues:**
- GitHub Actions DMG artifacts are only 46.9MB (should be ~200-240MB like local .app)
- Downloaded DMG shows "damaged and can't be opened" error
- CI appears to complete successfully but produces broken artifacts
- 180MB size difference between local .app (228MB) and CI DMG (46.9MB)

## Root Cause Analysis

### 1. bundle_dmg.sh Script Failure

The bundle_dmg.sh script is generated by Tauri during the build process. Running it manually shows:

```bash
$ bash -x ./bundle_dmg.sh
...
+ [[ -z '' ]]
+ echo 'Not enough arguments. Run '\''create-dmg --help'\'' for help.'
Not enough arguments. Run 'create-dmg --help' for help.
+ exit 1
```

**Why this happens:**
- Tauri's CLI is supposed to invoke this script with proper arguments
- The script expects: source directory, DMG name, volume name, etc.
- Tauri generates the script but something in the invocation chain is broken

### 2. Local vs CI Discrepancy

**Local (.app bundle):**
- Size: 228MB
- Location: `desktop-ui/src-tauri/target/release/bundle/macos/TS2Go Desktop.app`
- Contains: ts2go-cli, node runtime, parser, mappings
- Successfully created before DMG step fails

**CI (DMG artifact):**
- Size: 46.9MB (should be ~200-240MB compressed)
- "Damaged and can't be opened" error
- Successfully uploaded but incomplete

### 3. Potential Causes

**Option A: CI succeeds where local fails**
- CI might have different Tauri version or environment
- bundle_dmg.sh succeeds in CI but creates incomplete DMG
- Node.js runtime or other components missing from CI build

**Option B: CI also fails but workflow doesn't catch it**
- Makefile error handling might not propagate to workflow
- Partial/corrupt DMG gets copied to release/ directory
- Workflow uploads whatever exists in release/stable/macos/

**Option C: Platform-specific build differences**
- Local is Apple Silicon (arm64) with universal binary attempts
- CI might be building x86_64 only or missing universal binary components
- Size difference could be missing architecture binaries

## Proposed Solutions

### Solution 1: Skip DMG, Use .app + Manual Packaging (Quick Fix)

**Modify Makefile:**
```makefile
build-desktop: build-cli
    # ... existing steps ...
    cd desktop-ui && npm ci && npm run tauri:build -- --bundles app
    # Build only .app, skip DMG
    
    # Manually create DMG if needed
    @if [ "$(PLATFORM)" = "macos" ]; then \
        hdiutil create -volname "TS2Go Desktop" \
            -srcfolder "desktop-ui/src-tauri/target/release/bundle/macos/TS2Go Desktop.app" \
            -ov -format UDZO "release/stable/macos/TS2Go-Desktop-v$(VERSION).dmg"; \
    fi
```

**Pros:**
- Bypasses broken bundle_dmg.sh
- Uses reliable hdiutil directly
- Should work consistently local and CI

**Cons:**
- Loses Tauri's DMG customization (icons, window position)
- Need to manually configure DMG appearance

### Solution 3: Add Comprehensive Verification (Safety Net)

**Add to Makefile after Tauri build:**
```makefile
build-desktop: build-cli
    # ... existing build steps ...
    
    # Verify build artifacts before copying
    @echo "🔍 Verifying build artifacts..."
    @if [ "$(PLATFORM)" = "macos" ]; then \
        APP_PATH="desktop-ui/src-tauri/target/release/bundle/macos/TS2Go Desktop.app"; \
        if [ ! -d "$$APP_PATH" ]; then \
            echo "❌ ERROR: .app bundle not found"; \
            exit 1; \
        fi; \
        APP_SIZE=$$(du -sm "$$APP_PATH" | cut -f1); \
        if [ $$APP_SIZE -lt 200 ]; then \
            echo "❌ ERROR: .app bundle too small ($$APP_SIZE MB, expected >200MB)"; \
            exit 1; \
        fi; \
        if [ ! -f "$$APP_PATH/Contents/Resources/bin/ts2go-cli" ]; then \
            echo "❌ ERROR: ts2go-cli missing from .app"; \
            exit 1; \
        fi; \
        if [ ! -f "$$APP_PATH/Contents/Resources/bin/node" ]; then \
            echo "❌ ERROR: node runtime missing from .app"; \
            exit 1; \
        fi; \
        echo "✅ .app bundle verified ($$APP_SIZE MB)"; \
    fi
```

### Solution 4: CI-Specific Fix

**Update .github/workflows/release-alpha.yml:**
```yaml
- name: Verify build artifacts
  shell: bash
  run: |
    echo "Verifying build artifacts..."
    if [ "${{ matrix.platform }}" == "macos-latest" ]; then
      # Check .app first
      APP_PATH="desktop-ui/src-tauri/target/release/bundle/macos/TS2Go Desktop.app"
      if [ ! -d "$APP_PATH" ]; then
        echo "❌ ERROR: .app not found"
        exit 1
      fi
      
      APP_SIZE=$(du -sm "$APP_PATH" | cut -f1)
      echo "📦 .app size: ${APP_SIZE}MB"
      
      if [ $APP_SIZE -lt 200 ]; then
        echo "❌ ERROR: .app too small (${APP_SIZE}MB, expected >200MB)"
        exit 1
      fi
      
      # Check DMG
      DMG_PATH=$(find release/stable/macos -name "*.dmg" | head -1)
      if [ -n "$DMG_PATH" ]; then
        DMG_SIZE=$(du -sm "$DMG_PATH" | cut -f1)
        echo "💿 DMG size: ${DMG_SIZE}MB"
        
        if [ $DMG_SIZE -lt 100 ]; then
          echo "⚠️  WARNING: DMG seems too small, removing it"
          rm "$DMG_PATH"
          echo "📦 Will create DMG manually..."
          hdiutil create -volname "TS2Go Desktop" \
            -srcfolder "$APP_PATH" \
            -ov -format UDZO "release/stable/macos/TS2Go-Desktop.dmg"
        fi
      fi
    fi
```
